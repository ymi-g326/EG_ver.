# INSPECT: 公開された運用・軌道解析システムとの照合

確認日：2026-11-12。現場訪問や実運用担当者による認証ではなく、一次資料との照合。

## 比較対象と判断

| 一次資料 | 確認した内容 | EGへの採用・境界 |
|---|---|---|
| [FreeFlyer: 2D Map](https://ai-solutions.com/_help_Files/2d_map.htm) | 正距円筒地図、座標系、地図範囲・中心、衛星直下点による中心指定、緯経度グリッドを設定できる | 全世界／衛星中心／参照地点中心、拡大・移動、目盛り、地上軌跡と時刻を採用 |
| [NASA Open MCT](https://nasa.github.io/openmct/) | JPL等で利用される運用データ可視化の枠組み。ストリーミング・履歴・画像・タイムライン・手順を扱う | 表示時刻、入力値・生成音の記録、出典を追える構成を採用。EGは機体テレメトリ未接続 |
| [ESA Envisat operations（アーカイブ）](https://www.esa.int/Enabling_Support/Operations/Envisat_operations) | 運用は軌道予測・衛星状態監視・計画・指令・地上局など複数機能から構成される | INSPECTは公開軌道・環境・音楽変換を調べるビュー。指令送信・受信確認・ミッション実行監視は実装していない |
| [NASA Display Standard, Appendix F](https://www.nasa.gov/reference/appendix-f-vol-2/) | 現在モード、古いデータ、アラートの意味を示す。緊急・警告は赤、注意は黄、助言は青 | 色だけで状態を伝えず、出典・元期・欠測等を明記。赤道は薄い静的な基準線で、明示的な凡例を付ける |
| [FAA Flight Deck Displays: Color](https://hfcc.dot.gov/publications/docs/GeneralGuidance/zz_FAA_GeneralGuidanceDoc_Chapter_03_Section_07.html) | 航空機の警告・注意等には用途に応じた色の設計がある | 航空機の操縦用画面と衛星軌道解析画面は用途が異なる。EGが航空・宇宙用の認証基準を満たすとは説明しない |

「赤道は赤」という普遍的な規定は、この調査では確認していない。非警告の地理的な線として区別するというEG側の設計判断であり、実機アラート画面にそのまま適用する勧告ではない。

## 実装した科学的な区分

- 衛星位置：公開TLEとSGP4による推定。緯度・経度・楕円体高度、TEME速度の大きさを明記。
- 3D：半径6371 kmの球体近似、描画半径は1＋高度/6371。高さの誇張はない。楕円体形状・地形は描画しない。衛星マーカー・線幅は視認用。
- 軌道線：−46〜＋94分を15秒刻みで計算。過去線も推定であり、受信した航跡ではない。
- 参照地点：ユーザー入力の緯度・経度・楕円体高。初期値35°N,139°Eは例示で、実際の接続局を表さない。座標は端末内で計算する。
- 方位・仰角・斜距離：satellite.jsでSGP4位置を地球固定座標へ変換し、参照地点から計算。
- 通過：指定仰角マスクの上昇／最大仰角／下降を予測。最大24時間先、TLEの7日というアプリ上の有効期間で打ち切る。交差探索の刻みは実際の精度保証ではない。
- 可視範囲の線：球体近似の幾何学的マスク境界。カメラの撮影範囲、電波の到達保証、肉眼での可視性を表さない。
- 画像・気象：センサー・モデルと個別時刻を表示。てんこう2から直接受信した画像・気象ではない。

## 次の専門家レビューで確認する点

1. NUCC・運用側が提示できる実受信データ、復号仕様、時刻系、品質フラグ、公開範囲。
2. 運用側の追跡ソフトと同じTLE・参照地点・マスクを指定した通過予測の数値比較。
3. 表示高度の定義、球体近似の説明、地上軌跡と軌道の区別が十分か。
4. 実際の会場画面での文字・線・色の視認性。観測データがない項目を運用中に見せていないか。

公開資料から得た画面上の特徴と、EG独自の作曲・展示表現を混同しない。
